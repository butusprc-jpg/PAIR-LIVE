# Round and report epochs

Migration `026_round_reset_epoch.sql` assigns existing rounds to epoch 1 and adds an epoch to each new round. The reset action appends a new epoch and an audit event. It never deletes rounds, entries, OCR evidence, ledger rows, top-ups, withdrawals, broadcasts, or idempotency keys. Round IDs continue increasing globally.

The admin-only reset endpoint requires an authenticated V5 `admin` role, a one-use mutation challenge, a unique request key, and the exact phrase `ยืนยันเริ่มใหม่`. A PostgreSQL transaction takes the epoch advisory lock before the round-engine lock and locks the broadcast outboxes before it checks for an open/closing round or an in-flight delivery. Round and countdown mutations take a shared epoch advisory lock first. A repeated request key returns the original result; a reset of an empty epoch is a no-op.

Normal round, entry, evidence, participation, daily report, countdown, and broadcast queries use the current epoch. Older entries remain in their original state, including `PENDING`. Database triggers reject changes to archived rounds and entries so later code cannot settle or debit an archived entry by accident. The admin evidence endpoint can still retrieve archived evidence by round ID for audit.

For an audit, query `round_reset_epochs` and join `rounds.epoch_id` to the requested epoch. Restoring an archived epoch to normal operation is deliberately unavailable in the UI or API; it requires a separately reviewed database procedure that first reconciles pending entries, in-flight notifications, and the unique unfinished-round constraint. Do not change the current epoch by editing IDs or deleting the latest epoch row.

Before any production rollout, apply migration 026 with the database migration role. Migration 026 revokes `PUBLIC` access to `round_reset_epochs`; grant the private application role `SELECT` and `INSERT` on the table plus `USAGE` on its identity sequence. The round and reset paths use advisory locks, so the runtime role must not receive `UPDATE` or `DELETE` on the epoch table. Grant the actual worker role only the privileges its paths require. The production role names and grants are not configured in this repository; verify their effective grants before rollout.

Acceptance is blocked for a non-owner runtime role: `round_entries` has forced member-only RLS, so admin reset preview and archived-entry counts currently see zero rows without a member scope. Do not enable reset with such a role until a narrowly scoped admin read policy and its server-only transaction context are reviewed and tested. Never bypass this by granting a broad role or disabling RLS.
